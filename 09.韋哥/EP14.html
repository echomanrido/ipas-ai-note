Section 01

任務與資料量模型配對矩陣

基本必考
原廠簡報向量圖解 2：任務與資料量核心原則 重點一

【核心觀念】選模型兩大靈魂問題

1. 要預測什麼？（分類、回歸、分群、降維、時間序列）決定了輸出層激活函數與損失函數。
2. 有多少資料？ 模型參數量必須與樣本數嚴格匹配。小資料用大模型會把雜訊當規律，導致嚴重過擬合；大資料用簡單線性模型則會欠擬合。

資料量分級選型指南 (Data Scale)

小資料規模 < 數千筆
線性模型 / 淺層決策樹 / Lasso / Ridge

參數少、結構單純、高度可解釋、不易過擬合。高維小樣本情境推薦使用支持向量機 (SVM)。

中資料規模 數千 ~ 數十萬筆
隨機森林 / XGBoost / LightGBM

表格資料 (Tabular) 的絕對王者。訓練速度與記憶體消耗平衡佳，天然支援非線性關係。

大資料規模 > 百萬筆 / 非結構化
深度學習 (CNN / Transformer / MLP)

適合影像、語音、自然語言等複雜特徵提取，需大量標註資料與高階 GPU 算力餵飽參數。

【必考題型解析】房仲平台成交價預測

題目情境： 房仲業者需要預測房屋成交價（連續數值），資料存在複雜非線性關係，且內部稽核要求提供「整體特徵重要性」說明。
破題解法： 成交價為回歸任務，排除分類模型；存在非線性關係排除純多元線性回歸；選用隨機森林回歸 (Random Forest Regressor)。隨機森林天然能計算特徵分割時的不純度減少量，自動提供全域特徵重要性 (Feature Importance)。

Section 02

可解釋性需求與 SHAP 瀑布流模擬

高頻考點
原廠簡報向量圖解 3：高解釋性 (白箱) vs 低解釋性 (黑箱) 重點二
SHAP (Shapley Value)

單筆 + 整體兼具。博弈論貢獻分配，可精準算出每個特徵對「單一案件」的加減分貢獻。

LIME

單筆局部解釋。在待測樣本周圍擾動資料，用可解釋的線性模型局部逼近黑箱行為。

PDP 部分相依圖

全域整體趨勢。固定其他特徵，檢視某 1~2 個特徵數值邊際變動對整體模型預測的平均影響。

全域特徵重要性 (FI)

僅限宏觀統計。說明哪些特徵在整體訓練中權重最大，絕對無法說明單一客戶被拒原因。

Grad-CAM

電腦視覺專屬。利用最後卷積層梯度生成熱力圖 (Heatmap)，展示模型判讀圖片時關注的區域。

【高頻防雷警訊】開場貸款審核拒絕題

考題陷阱： 題目問「銀行使用 XGBoost 審查貸款，法規要求為每一位被拒絕的客戶提供清晰理由，應使用何種工具？」
錯誤選項： 特徵重要性 (Feature Importance) 只能看整體趨勢，無法針對單一個案提出法律抗辯依據；混淆矩陣是整體評估指標；Grad-CAM 僅限影像。唯一正解：SHAP（或 LIME）！

SHAP 單筆案件局部貢獻動態瀑布流 (Waterfall Plot)

基準基礎值 (Base Value) = 0.50，當預測值 $f(x) \ge 0.60$ 即核准貸款，低於則拒絕。

Section 03

偏差（Bias）與變異（Variance）權衡分析

數學架構題核心
原廠簡報向量圖解 5：系統性誤差 vs 訓練資料敏感度 重點四
GENERALIZATION ERROR DECOMPOSITION

泛化誤差可嚴格拆解為三部分：
• 偏差平方 ($\text{Bias}^2$)：簡化模型假設帶來的系統性錯誤。
• 變異 ($\text{Variance}$)：模型對訓練集擾動產生的預測波動。
• 不可約誤差 ($\sigma^2$)：環境底噪，任何模型皆無法消除。

① 低偏差 · 低變異 (理想狀態)

預測點緊湊聚集於紅心中央。模型結構容量與資料複雜度完美匹配，訓練集與驗證集皆獲得極佳精確度。

建議對策：保持現有超參數與架構，進行線上 A/B 測試。
高偏差改善 (欠擬合)
  • 換用更複雜模型 (如線性轉樹集成)
  • 增加特徵工程、多項式特徵
  • 減少正則化強度 (降低 $\lambda$)
  • 增加訓練輪數 (Epochs)
高變異改善 (過擬合)
  • 擴充訓練資料量或資料增強
  • 增加 L1/L2 正則化懲罰
  • 使用 Dropout、提前停止 (Early Stop)
  • Bagging 集成取平均以降低變異
Section 04

部署限制與邊緣運算模型壓縮

工程落地關鍵
原廠簡報向量圖解 4：硬體環境限制與模型壓縮對策 重點三
【邊緣三大硬體限制】記憶體小、算力弱、耗電緊

工廠產線攝影機或 IoT 終端常常沒有獨立高階 GPU。如果直接部署 ResNet-152 或大型 Transformer，推論時間往往高達數秒甚至造成記憶體溢位 (OOM)。解題原則：選輕量架構（如 MobileNet）+ 剪枝 (Pruning) + 模型量化 (Quantization)。

邊緣裝置 / IoT / 手機

算力極度受限、散熱條件差、依賴電池供電

輕量模型 (MobileNet) 採用深度可分離卷積 (Depthwise Separable Convolution)，參數量大幅減少 80~90%。
剪枝 (Pruning) 移除神經網路中權重接近 0 的無效連線，大幅減少運算參數量。
INT8 量化 (Quantization) 將 32-bit 浮點數轉換為 8-bit 整數，模型體積縮減 75%，大幅釋放記憶體。
適用：產線即時瑕疵檢測、無人機邊緣運算

毫秒級即時響應 (< 20ms)

高頻金融交易、搜尋引擎推薦、即時競價

快取機制 (Cache Layer) 使用 Redis 預存高頻熱門查詢結果，命中時直接回傳，繞過模型推論。
知識蒸餾 (Knowledge Distillation) 讓輕量「學生模型」學習大型「教師模型」的軟標籤 (Soft Labels) 輸出分佈。
推論引擎優化 (TensorRT/ONNX) 算子融合 (Kernel Fusion)，最大化硬體吞吐量與管線併發。
適用：外送派單演算法、防偽刷卡即時攔截

雲端資料中心 (Cloud Center)

算力充沛、多張 GPU 叢集、記憶體無瓶頸

巨量參數基礎模型 (LLM) 部署 70B+ 大型語言模型或超大型多模態 Vision-Language 架構。
多模型堆疊集成 (Stacking) 多個異質模型 (XGBoost + LightGBM + MLP) 進行兩階段堆疊融合預測。
批次離線排程處理 針對無即時性需求的隔日分析報表，以高並行管線執行計算。
適用：跨國氣象數值預報、大語言模型訓練

RAG 檢索策略與倒數排名融合 (RRF)

高階架構題
原廠簡報向量圖解 7：RAG 檢索策略三巨頭 (語意 vs BM25 vs 混合) 重點六
【超出指引考點】為什麼純語意向量搜尋會抓錯合約條款？

原廠考題： 企業內部合約知識庫中，針對特定編號（例如「合約 A1024 違約責任條款」）進行檢索，發現向量搜尋經常抓成其他條款，應如何最佳化？
解析： 語意向量（Dense Vector）擅長同義詞與泛化語意，但對精確代碼、型號極度不敏感；BM25（Sparse Term Matching）擅長字字符合但無語意泛化。唯一正解：混合搜尋（Hybrid Search）結合 RRF 倒數排名融合！
