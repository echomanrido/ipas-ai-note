  • 考科結構：必考 L21「AI 技術應用與規劃」＋擇一選考 L22「大數據處理分析」或 L23「機器學習技術與應用」（各含約 25% Python 閱讀題）。

  • 數據現象：到考人數從 455 人暴增至 2,304 人，獲證率由 62.64% 一路降至 35.20%，各科難度輪流波動大。
中文術語 English Term 本專案角色與生活化白話解釋
獲證率（目標變數） Certification Rate (Target y) 核發證書人數 ÷ 到考人數（含跨次補考）。是模型要預測的連續百分比數值。
單科最低瓶頸特徵 Bottleneck Pass Rate (min_sub) 取該梯各科及格率的最小值（如木桶理論最短木板），專門捕捉「卡關效應」。
Z-Score 標準化 StandardScaler 將 0/1 級別旗標、1～8 梯次與 20%～85% 及格率統一縮放至均值 0、標準差 1，確保 L2 懲罰公平。
脊迴歸 / L2 正則化 Ridge Regression (L2 Penalty) 在誤差函數加上 $\alpha \sum w_j^2$，壓抑過大權重，防止 12 筆小樣本出現極端預測。
時間順序切分 Chronological Split (shuffle=False) 用早期梯次訓練、預測最新梯次（115-3/115-4 與 115-1/115-2），杜絕未來資料洩漏（Data Leakage）。
留一交叉驗證 Leave-One-Out CV (LOOCV) 小樣本必備：輪流留 1 梯當考題、其餘 11 梯訓練，完整評估 12 梯的泛化誤差。
天真基準線 Naive Baseline 直接猜「同級別歷史平均獲證率」。若 ML 模型連這個都打不贏，就標記為 FAIL 不可上線。

3. 階段一：特徵工程公式圖文詳解與歷屆走勢圖

圖解 3.1｜跨級別特徵對齊

為什麼初級（2 科）和中級（3 科）能放進同一個機器學習模型？

不同級別的考科數量不同，直接塞進表格會產生大量缺值（NaN）。階段一的核心任務就是把兩者抽象成一致的 5 維數值特徵向量。

圖解 3.2｜制度差異視覺化

一張圖看懂：為什麼初級有「互補救生圈」、中級是「雙鎖保險箱」？

公式 1｜單科瓶頸特徵（木桶效應）
$$\text{min\_sub}_i = \min\big(\text{core\_pass}_i,\; \text{spec\_pass}_i\big)$$

白話解釋：無論初級（單科不可低於 60 分）或中級（雙科皆須 70 分），只要有一科特別難，整體獲證率就會被「最短的木板」拖垮。

📌 115-4 初級實算範例：科目一及格率 31.68%、科目二 56.52% → 瓶頸特徵 $\text{min\_sub} = \min(31.68, 56.52) = \mathbf{31.68\%}$。中級 115-1 則是 L21=85.81%、L22=22.12%、L23=56.78% → $\text{min\_sub} = \mathbf{22.12\%}$。
公式 2｜Z-Score 特徵標準化
$$z_j = \frac{x_j - \mu_j}{\sigma_j}$$

白話解釋：「中級旗標」只有 0 與 1，但「科目及格率」是 22～86。若不先轉成相同尺度的 Z-Score，Ridge 的 L2 懲罰會對大尺度和小尺度特徵極度不公平。

📌 115-4 初級實算範例：全體 12 梯科目一平均 $\mu = 46.69\%$、標準差 $\sigma = 19.46\%$。代入 115-4 的 $31.68\%$ → $z_{\text{core}} = (31.68 - 46.69) / 19.46 = \mathbf{-0.7715}$（低於歷年平均約 0.77 個標準差）。
公式 3｜Ridge L2 正則化目標函數
$$\min_{\mathbf{w},\, b} \; \sum_{i=1}^{n} \big(y_i - (\mathbf{w}^\top \mathbf{z}_i + b)\big)^2 + \alpha \sum_{j=1}^{5} w_j^2$$

白話解釋：左半部追求「猜得越準越好」，右半部 $\alpha \sum w_j^2$ 負責「懲罰過度極端的權重」。當 $\alpha = 1.0$ 時，測試集 MAE 從 7.88%（$\alpha=0.1$）大幅降至 4.35%。

📌 115-4 初級完整端到端手算驗證：截距 $b=48.98\%$，代入 5 維 Z-Score 與權重 $[-3.23, -0.13, +4.02, +5.42, +3.39]$：
$\hat{y} = 48.98 + (-3.23)(-0.707) + (-0.13)(1.901) + (4.02)(-0.771) + (5.42)(-0.188) + (3.39)(-0.518) = \mathbf{45.14\%}$（實際官方為 46.88%，誤差僅 1.74%！）。

離線訓練 ↔ 線上推論雙向契約
① 為什麼要拆成兩個獨立 Python 檔？

離線訓練需要計算 LOOCV、SHAP/LIME 與繪製 2×2 驗證圖表；線上服務（main.py）則是 7×24 常駐 API，只需載入輕量級 .joblib 即可在數毫秒內回應預測請求。

② 雙檔之間的三大嚴格契約 (Contract)

1. 5 維特徵順序（is_mid, seq_idx, core_pass, spec_pass, min_sub）完全一致；2. min_sub 瓶頸定義不變；3. 推論必先經過訓練好的 StandardScaler。

③ 線上防呆與自動裁切設計

Pydantic 會自動攔截超過 0～100% 的異常輸入（回傳 HTTP 422），模型輸出亦會裁切至 0%～100% 並自動轉換為友善／警戒燈號，降低前端或 C# 串接負擔。

        Section 08
        
8. 核心產出檔案深度解析

      


      
      

        
      


      
      

        

          01
          
ipas_passrate_pipeline.joblib

          
來歷：由 stage2_train_eval.py 執行 joblib.dump() 產生。

          
內部結構：字典封裝 pipeline（含 StandardScaler 均值/標準差與 Ridge 權重）、feature_names、metrics 與 accuracy_verdict。

          
防呆原因：將 Scaler 與 Model 綁在同一 Pipeline，線上推論才不會發生「訓練／服務偏移（Training-Serving Skew）」。

        

        

          02
          
ipas_exam_stats.csv

          
來歷：由 stage1_data_features.py 彙整 114–115 年官方統計並輸出。

          
內部欄位：session, level, is_mid, seq_idx, core_pass, spec_pass, min_sub, cert_rate 共 8 欄 12 列（UTF-8-SIG 編碼，Excel 開啟不亂碼）。

          
防呆原因：每次 116 年新梯次放榜，只需於 CSV 末尾新增 1 列並重跑 Stage 2，即可完成模型迭代更新。

        

        

          03
          
main.py

          
來歷：於 Colab 獨立儲存格使用 %%writefile main.py 寫入。

          
推論管線：Pydantic 檢查數值界線（0～100%）→ 轉為 NumPy 陣列 → 呼叫 pipeline.predict() → 裁切至 0～100% 並附加難度警示與備考建議。

          
防呆原因：絕不可將 subprocess.Popen("uvicorn...") 寫進 main.py，否則會觸發遞迴啟動並造成 502 錯誤。

        Section 09
        
9. Ridge L2 正則化核心原理與互動權重衰減模擬器

      


      
      

        

          圖解 9.1｜三步驟白話圖解
          
為什麼 L2 正則化（$lpha$）像幫模型繫上「彈性安全帶」？

        

        

          
          

            
① 沒繫安全帶（$lpha = 0.1$ 過擬合）

            
            
生活比喻：死背 8 次考古題答案，遇到 115 年新題型就大失準，權重被單次雜訊拉偏。

          


          
          

            
② 黃金平衡點（$lpha = 1.0$ 最佳 ★）

            
            
生活比喻：用橡皮筋溫和收斂權重，抓住「核心科＋應用科＋瓶頸」主規律，新梯次照樣準。

          


          
          

            
③ 綁得太緊（$lpha = 5.0+$ 欠擬合）

            
            
生活比喻：懲罰太重把所有權重壓扁，不管考題多難都只會猜整體均值 48.98%。

          

        

      


      
      

        

          

            圖解 9.2｜單筆預測積木拆解
            
以最新「中級 115-2（實際 35.20%）」為例：模型怎麼一步步算出 36.80%？

          

          基準 48.98% → 最終 36.80%（誤差僅 1.60%）
        

        

          
        

      


      
      

        

          

            🔵 Ridge (L2 圓形約束) — 本案選用
            保留所有特徵
          

          
在 iPAS 數據中，core_pass 與 min_sub 高度相關（共線性）。L2 圓形平滑約束會讓兩者公平分攤權重（+4.02 與 +3.39），維持模型穩定不震盪。

        

        

          

            🔸 Lasso (L1 菱形約束) — 對照參考
            稀疏歸零
          

          
L1 菱形尖角傾向把共線特徵中的其中一個直接壓成 0（自動特徵篩選）。適合數百維高維資料，但在本案 5 維精選特徵中會損失珍貴訊號。

        

      


      
      

        

          
        


        
        

          

            
🎛️ 即時調整正則化強度 $\alpha$（觀察權重收縮與誤差）

            α = 1.0
          

          
          

            0.1 (過擬合)
            1.0 (最佳 ★)
            2.0 (偏保守)
            5.0 (欠擬合)
          

          

            

              
測試集 MAE

              
4.35%

            

            

              
測試集 RMSE

              
5.77%

            

            

              
測試集 R²

              
0.7621

            

          

          

            最佳平衡點（α = 1.0）：適度壓抑共線特徵權重，測試集誤差比天真基準線低 64.5%，兼顧準確度與穩定性。
          

        

      


      
      

        

          
            

              超參數 / 設計
              本專案設定
              工程意義與調整原則
            

          
          
            

              alpha (L2 強度)
              1.0
              控制權重收縮程度；小樣本且特徵具共線性時通常從 0.1～10 網格搜尋。
            

            

              StandardScaler
              fit on X_train only
              嚴格僅在訓練集計算均值與標準差，避免測試集統計量外洩。
            

            

              LeaveOneOut()
              12-Fold LOOCV
              當 N < 30 時，LOOCV 比傳統 5-Fold 更能充分利用每一筆珍貴考次資料。
