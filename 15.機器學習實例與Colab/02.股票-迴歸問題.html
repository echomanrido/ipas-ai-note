在量化建模流程中，面對金融市場「高雜訊、非平穩且嚴禁未來資訊洩漏」的現場痛點，我們採用 監督式迴歸（Supervised Regression）：先以 rolling() 與 pct_change() 建構均線、漲跌幅與量能變化特徵；接著嚴格設定 shuffle=False 切分訓練與測試集，訓練 100 棵決策樹組成的隨機森林，與 Naive Baseline 比對誤差並自動輸出「✅ 準 / ❌ 不準」判定；最後將雙 .pkl 模型封裝進 FastAPI 提供雙端點即時預測。

Section 03 · Stage 1 Data & EDA

3. 階段一：特徵工程數學核心、價量圖表與 CSV 前 10 筆

📊 為什麼抓股價要抓這 5 個欄位（OHLCV）？

單根 K 線與量能解剖
1. Open / High / Low（開盤、最高、最低） 紀錄當天盤中多空交戰的「振幅區間」與早盤跳空情緒，是判斷支撐壓力與後續擴充波動率特徵（如 ATR）的基礎。
2. Close（收盤價）— 最核心基準 經過整天搓合後的最終共識價格，是計算 MA_3、MA_5、Daily_Return 與預測目標 Target 的唯一依據。
3. Volume（成交量）— 辨別真突破與假反彈 價格上漲如果沒有成交量配合，往往是虛漲；抓取 Volume 才能算出 Volume_Change，讓模型知道今天是「放量攻擊」還是「量縮觀望」。
數學核心 / Math Core (全 5 特徵 + 雙目標)

技術指標與迴歸目標數學定義

1. 當日漲跌幅：$$\text{Daily\_Return}_t = \frac{\text{Close}_t - \text{Close}_{t-1}}{\text{Close}_{t-1}}$$
2. 成交量變化率：$$\text{Volume\_Change}_t = \frac{\text{Volume}_t - \text{Volume}_{t-1}}{\text{Volume}_{t-1}}$$
3. $n$ 日移動平均：$$\text{MA}_n(t) = \frac{1}{n}\sum_{i=0}^{n-1}\text{Close}_{t-i}\quad (n=3, 5)$$
4. 雙預測目標：$$\text{Target}_t = \text{Close}_{t+1},\quad \text{Target\_Ret5d}_t = \left(\frac{\text{Close}_{t+5}}{\text{Close}_t}-1\right)\times 100\%$$
量化交易意義 & 工程原則

這 5 個特徵分別在捕捉什麼市場訊號？

  • Close（今日收盤價）：提供模型目前的「絕對價格錨點」。
  • MA_3 / MA_5（短中期均線）：過濾單日雜訊，捕捉 3 日與 5 日的趨勢方向（如站上均線代表轉強）。
  • Daily_Return（當日漲跌幅）：衡量短期動能強弱，避免只看價格而忽略漲跌幅度。
  • Volume_Change（成交量變化率）：量價配合驗證——上漲伴隨放量代表買盤真實。
特徵對齊原則：階段一保留 Lag_1_Close 於 CSV 中；階段二與階段三嚴格對齊使用 Close, MA_3, MA_5, Daily_Return, Volume_Change 5 維特徵。
① 均線 (MA_3 / MA_5) 的生活比喻

就像量體重：每天早上受喝水影響會上下波動，但看「最近 3 天與 5 天平均體重」，就能看清真正在變重還是變輕。

② 量能變化 (Volume_Change) 的意義

就像商店營業額：今天商品漲價（收盤漲）但上門客人變少（量縮），代表買氣虛弱；放量上漲才代表趨勢有支撐。

③ 為什麼要 shift(-1) 與 dropna()？

訓練 AI 就像做考古題：必須把「明天的答案」往回對齊到「今天的題目」旁邊；頭尾缺少題目或答案的列必須整列刪除。

Section 04 · Stage 2 Training & Validation

4. 階段二：時序切分原則、Baseline 對照與驗證儀表板

為何嚴禁 shuffle=True

防止未來資訊洩漏 (Look-ahead Bias)

金融時間序列具有強烈前後相依性。必須使用 train_test_split(X, y, test_size=0.2, shuffle=False)，確保模型只用「過去 80% 交易日」來預測「未來 20% 交易日」。

生活化比喻 · Naive Baseline

模擬考不能偷看答案，還要打敗懶人基準線

Naive Baseline 就是「懶人猜法」：直接拿今天收盤價當作明天預測值。若模型的 MAE 與 RMSE 無法低於 Baseline，代表模型還沒學到有效趨勢，需拉長抓取區間（如 1y）。

🔍 實戰誠實結論：預測「具體價格」或「報酬率」到底準不準？

不可直接用於實盤
  • 預測「具體價格」通常不準：當 MAE > Naive Baseline MAE（例如實測 294.22 > 135.00）且殘差全偏同側時，代表模型表現不如「直接猜明天等於今天」，主因是 1mo 樣本過少與樹狀模型無法外推反彈波段。
  • 預測「未來 5 天報酬率」較穩但仍受雜訊限制：雖然報酬率消除了股價絕對位階的偏差，但仍須同時檢驗「MAE 是否小於 0% 基準線」與「漲跌方向準確率（Directional Accuracy）是否 > 55%」，未達標即屬無效預測。

📐 階段二評估指標完整計算式與實測驗算 (Formulas & Step-by-Step Breakdown)

對應終端輸出結果
1. MAE 與 Baseline MAE（平均絕對誤差）
$$\text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$

將測試集每筆「實際值與預測值差距的絕對值」加總後平均。實測 294.22 > 135.00，表示平均每天誤差比「直接猜今天收盤價」還多出 159.22 元。

2. RMSE（均方根誤差）
$$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}$$

先將誤差平方再平均最後開根號，會放大極端大誤差的懲罰。實測 300.83 > 294.22，代表測試集各筆誤差都很巨大。

3. MAPE 與 R²（百分比誤差與決定係數）
$$\text{MAPE} = \frac{100\%}{n}\sum\left|\frac{y_i - \hat{y}_i}{y_i}\right|,\quad R^2 = 1 - \frac{\sum(y_i - \hat{y}_i)^2}{\sum(y_i - \bar{y})^2}$$

實測 R² = -16.8612 為負數，代表模型誤差遠大於「直接猜測試集平均值 $\bar{y}$」。

4. 方向準確率（Directional Accuracy）
$$\text{DirAcc} = \frac{\text{Count}(\text{sign}(y_i) = \text{sign}(\hat{y}_i))}{n} \times 100\%$$

測試集共 3 筆，猜對 2 筆漲跌方向（2 / 3 × 100% = 66.7%），但幅度誤差 8.12% > 1.13%（零基準線），因此仍判定不準。

import yfinance as yf
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

# 1. 抓取聯發科 (2454.TW) 最近 1 個月、日 K 線 (1d) 歷史資料
#    progress=False 可關閉下載進度條，保持輸出版面乾淨
df = yf.download("2454.TW", period="1mo", interval="1d", progress=False)

# 相容性處理：新版 yfinance (>= 0.2.40) 會回傳雙層 MultiIndex 欄位 (如 ('Close', '2454.TW'))
# 這裡將其降維成單層欄位 ('Close', 'Open'...)，避免後續計算與模型輸入出錯
if isinstance(df.columns, pd.MultiIndex):
    df.columns = df.columns.get_level_values(0)

# 強制依日期由舊到新排序（時間序列計算 rolling 與 shift 前的必要步驟）
df = df.sort_index()[["Open", "High", "Low", "Close", "Volume"]].copy()

# 2. 建立基礎技術指標特徵（皆以當日 t 以前可取得的資訊計算，絕不使用未來資料）
df["Lag_1_Close"] = df["Close"].shift(1)             # 昨日收盤價：將收盤價往下移 1 列
df["MA_3"] = df["Close"].rolling(window=3).mean()    # 3 日移動平均線：含今日共 3 天平均
df["MA_5"] = df["Close"].rolling(window=5).mean()    # 5 日移動平均線：含今日共 5 天平均
df["Daily_Return"] = df["Close"].pct_change()        # 當日漲跌幅：(今日收盤 - 昨日收盤) / 昨日收盤
df["Volume_Change"] = df["Volume"].pct_change()      # 成交量變化率：衡量今日量能放大或萎縮幅度

# 3. 定義雙迴歸預測目標：
#    - Target          : 明日具體收盤價 (元)，shift(-1) 把明天收盤價移到今天作為標準答案
#    - Target_Return_5d: 未來 5 天漲跌幅百分比 (%)，衡量未來 5 個交易日的累計報酬率
df["Target"] = df["Close"].shift(-1)
df["Target_Return_5d"] = (df["Close"].shift(-5) / df["Close"] - 1) * 100

# 4. 資料清洗與防呆：
#    - 若前一日成交量為 0，pct_change() 會產生無限大 (inf)，先替換為 NaN
#    - 再透過 dropna() 一次清除前 4 列 (MA_5 缺失) 與最後 1 列 (Target 缺失)
df.replace([np.inf, -np.inf], np.nan, inplace=True)
df_clean = df.dropna().copy()

# 儲存整理好的完整 DataFrame（含日期索引）為 CSV
csv_filename = "2454_regression_data.csv"

df_data = pd.read_csv("2454_regression_data.csv", index_col=0, parse_dates=True)

# 嚴格對齊階段三 FastAPI 接收的 5 個特徵欄位順序
feature_cols = ["Close", "MA_3", "MA_5", "Daily_Return", "Volume_Change"]
X = df_data[feature_cols]
y = df_data["Target"]                       # 目標 A：明日具體價格
y_ret5d = df_data["Target_Return_5d"]       # 目標 B：未來 5 天報酬率 (%)

# 2. 切分訓練集 (80%) 與測試集 (20%)

#    - model_ret : 預測「未來 5 天報酬率 (%)」
model = RandomForestRegressor(n_estimators=100, random_state=42)

model_ret = RandomForestRegressor(n_estimators=100, random_state=42)
model_ret.fit(X_train, y_ret_train)

# 產生訓練集與測試集預測值
y_train_pred = model.predict(X_train)
y_test_pred = model.predict(X_test)
y_ret_pred = model_ret.predict(X_test)
print(f"【報酬率模型評估】未來 5 天報酬率 MAE: {mean_absolute_error(y_ret_test, y_ret_pred):.2f} %")

# 建立 Naive Baseline 基準線：假設「明日收盤價 = 今日收盤價」
# 若 ML 模型連這個最簡單的基準都打不敗，代表模型尚未學到有效訊號

ret_mae = mean_absolute_error(y_ret_test, y_ret_pred)
ret_baseline_mae = mean_absolute_error(y_ret_test, np.zeros_like(y_ret_test))
dir_acc = np.mean(np.sign(y_ret_test.values) == np.sign(y_ret_pred)) * 100

price_ok = (mae < baseline_mae) and (mape < 2.0)
ret_ok = (ret_mae < ret_baseline_mae) and (dir_acc > 55.0)

ret_verdict = "✅ 準（具備趨勢方向參考性）" if ret_ok else "❌ 不準（方向準確率不足或未贏過零基準線）"

sse = np.sum(sq_errs)

import joblib
import pandas as pd
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

# 1. 初始化 FastAPI 應用程式實例（會自動產生 /docs Swagger 互動文件）
app = FastAPI(title="聯發科 (2454.TW) 股價預測 API / Stock Prediction API", version="1.0.0")

# 2. 伺服器啟動時預先載入「具體價格模型」與「5日報酬率模型」（相容含判定標籤的 dict 或純模型）
def _load_bundle(path: str):
    try:
        obj = joblib.load(path)
        if isinstance(obj, dict) and "model" in obj:
            return obj["model"], obj.get("verdict", "未知")
        return obj, "未附帶驗證標籤（建議重新執行階段二）"
    except FileNotFoundError:
        return None, "模型檔案尚未產生"

model_price, verdict_price = _load_bundle("2454_reg_model.pkl")
model_ret, verdict_ret = _load_bundle("2454_ret5d_model.pkl")

# 3. 定義輸入請求的 Pydantic 資料驗證模型（附 Swagger 預設範例數值）
class StockFeatures(BaseModel):
    Close: float = Field(..., gt=0, description="今日收盤價 (TWD)")
    MA_3: float = Field(..., gt=0, description="3日移動平均線 (TWD)")
    MA_5: float = Field(..., gt=0, description="5日移動平均線 (TWD)")
    Daily_Return: float = Field(..., description="當日漲跌幅 (例如 0.012 代表 +1.2%)")
    Volume_Change: float = Field(..., description="成交量變化率 (例如 0.15 代表 +15%)")

    model_config = {
        "json_schema_extra": {
            "example": {
                "Close": 1280.0,
                "MA_3": 1275.0,
                "MA_5": 1268.0,
                "Daily_Return": 0.012,
                "Volume_Change": 0.15
            }
        }
    }

# 4. 定義兩種端點的回傳 JSON 結構（明確附帶模型準確度判定）
class PricePredictionResponse(BaseModel):
    ticker: str
    mode: str
    current_close: float
    predicted_next_close: float
    predicted_change_pct: float
    accuracy_verdict: str

class ReturnPredictionResponse(BaseModel):
    ticker: str
    mode: str
    current_close: float
    predicted_5d_return_pct: float
    estimated_5d_target_price: float
    accuracy_verdict: str

def _to_df(features: StockFeatures) -> pd.DataFrame:
    return pd.DataFrame([{
        "Close": features.Close,
        "MA_3": features.MA_3,
        "MA_5": features.MA_5,
        "Daily_Return": features.Daily_Return,
        "Volume_Change": features.Volume_Change
    }])

# 5A. 端點一：預測「明日具體收盤價」
@app.post("/predict/price", response_model=PricePredictionResponse, summary="預測明日具體收盤價")
def predict_next_close(features: StockFeatures):
    if model_price is None:
        raise HTTPException(status_code=500, detail="2454_reg_model.pkl 尚未載入。")
    pred_close = float(model_price.predict(_to_df(features))[0])
    pred_change_pct = ((pred_close - features.Close) / features.Close) * 100
    return PricePredictionResponse(
        ticker="2454.TW",
        mode="next_day_close_price",
        current_close=round(features.Close, 2),
        predicted_next_close=round(pred_close, 2),
        predicted_change_pct=round(pred_change_pct, 2),
        accuracy_verdict=verdict_price
    )

# 5B. 端點二：預測「未來 5 天報酬率 (%)」
@app.post("/predict/return", response_model=ReturnPredictionResponse, summary="預測未來 5 天漲跌幅百分比")
def predict_5d_return(features: StockFeatures):
    if model_ret is None:
        raise HTTPException(status_code=500, detail="2454_ret5d_model.pkl 尚未載入。")
    pred_ret_pct = float(model_ret.predict(_to_df(features))[0])
    est_price = features.Close * (1 + pred_ret_pct / 100)
    return ReturnPredictionResponse(
        ticker="2454.TW",
        mode="5d_forward_return_pct",
        current_close=round(features.Close, 2),
        predicted_5d_return_pct=round(pred_ret_pct, 2),
        estimated_5d_target_price=round(est_price, 2),
        accuracy_verdict=verdict_ret
    )

        Section 08 · Persistence Deep Dive
        

          8. 核心產出檔案深度解析：2454_reg_model.pkl、2454_ret5d_model.pkl 與 .csv
        

        
執行階段二後產生的兩個 .pkl 檔案是整個 FastAPI 推論服務的大腦，以下完整拆解它們的來歷與內部結構。

      


      

        
      


      

        
💡 什麼是 .pkl / joblib 檔案？為什麼不用 CSV 或 JSON 存模型？

        

          在 Python 機器學習中，訓練好的隨機森林包含 100 棵決策樹的樹狀節點指標、分支門檻與葉節點預測值，這些結構複雜的物件只存在記憶體（RAM）裡，一旦程式結束就會消失。透過 joblib.dump(物件, "檔名.pkl")，系統會把記憶體中的 Python 物件序列化（Serialize）成高效率二進位檔案存到硬碟，讓 FastAPI（main.py）啟動時能用 joblib.load() 在幾毫秒內完整還原，無須重新訓練。
        

      


      

        

          

            01
            

              
2454_reg_model.pkl

              
具體價格迴歸「主模型」（預測明日收盤價 + 準度警語）

            

          

          約 150 KB ～ 500 KB
        


        

          
1. 它是如何產生的？（來歷）

          
在 stage2_train_eval.py 中，程式先依 shuffle=False 切出前 80% 訓練集訓練 100 棵決策樹，並將測試集 MAE 與 Naive Baseline 比較後，將模型與判定結果打包成字典寫入硬碟。

        


        

          
2. 檔案裡面存了什麼內容？

          
它裡面儲存了一個 Python 字典封裝，包含 RandomForestRegressor 物件與自動驗證標籤：

          
• "model"      : RandomForestRegressor(n_estimators=100, random_state=42)  # 100 棵決策樹
• "is_accurate": False  # 自動比對 MAE (294.22) vs Baseline (135.00) 的布林結果
• "verdict"    : "❌ 不準（誤差大於基準線，不可用於實盤）"
• feature_names_in_: ["Close", "MA_3", "MA_5", "Daily_Return", "Volume_Change"]

        


        

          
3. 為什麼要封裝 verdict 標籤？

          
避免線上 API 成為「盲目報明牌的黑盒子」。當 FastAPI 收到 Close=1280 等異常或區間外請求時，除了回傳數值，也能即時附上該模型在離線驗證時的真實可靠度警告。
