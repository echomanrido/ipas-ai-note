3. 階段一：特徵工程數學核心、價量圖表與 CSV 前 10 筆

特徵工程數學定義 (KaTeX) 與圖文深度解析

將原始股價與成交量轉換為尺度一致的 3 個動能狀態特徵，確保 PPO 神經網路穩定收斂。

3 大狀態特徵放大詳解
1. 日報酬率 (Daily Return)
r_t = (C_t - C_{t-1}) / C_{t-1}

核心意義： 消除股價絕對位階（無論聯發科在 1,000 元或 4,000 元），純粹衡量「單日漲跌百分比力道」。
實戰舉例： 若昨日收盤 3,390、今日收盤 3,725，則 r_t = (3725 - 3390) / 3390 = +9.88%，反映強烈的反彈買盤動能。

2. 三日均線乖離率 (MA3 Bias)
Bias_t = (C_t - MA3_t) / (MA3_t + 1e-8)

核心意義： 衡量目前股價偏離「近 3 日平均成本」多遠。因本案僅抓 1 個月資料，選用敏感度高的 MA3 捕捉短線轉折，並於分母加上 1e-8 防止除零錯誤。
判讀口訣： 正乖離過大代表短線追價過熱、易拉回；負乖離過深則可能出現跌深反彈機會。

3. Z-Score 標準化 (State Scaling)
z_t = (x_t - μ) / (σ + 1e-8)

核心意義： Close 是上千元、Volume 是上千萬、Return 卻只有 0.02，直接輸入神經網路會導致梯度嚴重失衡。Z-Score 將三個特徵統一轉換成「距離平均有幾個標準差」。
實戰數值： 約 95% 的正常交易日會落在 [-2, +2] 之間，> +2 代表極端強勢或爆量。

import numpy as np
import pandas as pd
import yfinance as yf
import gymnasium as gym
from gymnasium import spaces
from IPython.display import display

# ==============================================================================
# 步驟 1：資料抓取與 MultiIndex 欄位防呆處理
# ==============================================================================
ticker = "2454.TW"  # 聯發科在 Yahoo Finance 的台股代號
# 抓取最近 1 個月 (1mo) 的日 K 線 (1d)，progress=False 關閉下載進度條
df = yf.download(ticker, period="1mo", interval="1d", progress=False)

# [重要防呆] 新版 yfinance (>=0.2.40) 即使抓單一股票也可能回傳雙層 MultiIndex 欄位
# 若不扁平化，後續 df["Close"] 會變成 DataFrame 而非 Series，導致形狀錯誤
if isinstance(df.columns, pd.MultiIndex):
    df.columns = df.columns.get_level_values(0)

# ==============================================================================
# 步驟 2：計算技術動能指標與 Z-Score 標準化
# ==============================================================================
# 日報酬率：(今日收盤 - 昨日收盤) / 昨日收盤
df["daily_return_raw"] = df["Close"].pct_change()
# 3 日簡單移動平均線 (MA3)
df["ma3"] = df["Close"].rolling(window=3).mean()
# MA3 乖離率：衡量股價偏離短期均線的程度 (+1e-8 避免分母為 0)
df["ma3_bias_raw"] = (df["Close"] - df["ma3"]) / (df["ma3"] + 1e-8)
# 成交量變化率：將可能因前日量為 0 產生的 inf/-inf 強制轉為 0.0
df["volume_change_raw"] = df["Volume"].pct_change().replace([np.inf, -np.inf], 0.0)

# 移除前 2 筆因 rolling(3) 與 pct_change() 產生的空值 (NaN)
df = df.dropna().copy()

# 對三個市場指標進行 Z-Score 標準化：(數值 - 平均) / 標準差
# 目的：讓神經網路輸入維持在均值 0、標準差 1 附近，避免股價(上千元)與報酬率(0.01)尺度懸殊
for raw_col, norm_col in [
    ("daily_return_raw", "daily_return_norm"),
    ("ma3_bias_raw", "ma3_bias_norm"),
    ("volume_change_raw", "volume_change_norm"),
]:
    df[norm_col] = (df[raw_col] - df[raw_col].mean()) / (df[raw_col].std() + 1e-8)

# ==============================================================================

# 步驟 4：自訂符合 Gymnasium 標準的 StockTradingEnv 交易環境
# ==============================================================================
class StockTradingEnv(gym.Env):
    """聯發科單一標的強化學習交易環境"""
    metadata = {"render_modes": ["human"]}

    def __init__(self, df: pd.DataFrame, initial_balance: float = 1_000_000.0, fee_rate: float = 0.004):
        super().__init__()
        self.df = df.reset_index(drop=True)
        self.initial_balance = initial_balance  # 初始資金 100 萬台幣
        self.fee_rate = fee_rate                # 賣出時扣除台股手續費+證交稅約 0.4%

        # 定義動作空間：離散 3 個動作 -> 0=持有/觀望, 1=買進, 2=賣出
        self.action_space = spaces.Discrete(3)
        # 定義觀察空間：4 維連續浮點數向量 [持倉(0/1), 標準化報酬率, MA3乖離率, 成交量變化率]
        self.observation_space = spaces.Box(low=-np.inf, high=np.inf, shape=(4,), dtype=np.float32)
        self.reset()

    def _get_observation(self) -> np.ndarray:
        """組合當前交易日的 4 維狀態向量 (必須為 float32 以符合 SB3 規範)"""
        row = self.df.iloc[self.current_step]
        return np.array([
            float(self.position),
            float(row["daily_return_norm"]),
            float(row["ma3_bias_norm"]),
            float(row["volume_change_norm"]),
        ], dtype=np.float32)

    def reset(self, seed=None, options=None):
        """每個訓練回合 (Episode) 開始時重置資金與持倉狀態"""
        super().reset(seed=seed)
        self.current_step = 0
        self.position = 0          # 0 = 空手, 1 = 持倉中
        self.cash = self.initial_balance
        self.shares = 0.0
        self.entry_price = 0.0
        self.total_asset = self.initial_balance
        return self._get_observation(), {}

    def step(self, action: int):
        """執行 Agent 決策動作，推進一個交易日並計算獎勵 (Reward)"""
        current_price = float(self.df.loc[self.current_step, "Close"])
        daily_raw_ret = float(self.df.loc[self.current_step, "daily_return_raw"])
        reward = 0.0

        if action == 1:  # 動作 1：買進 (BUY)
            if self.position == 0:
                self.shares = self.cash / current_price  # 全倉買進換算股數
                self.cash = 0.0
                self.entry_price = current_price         # 紀錄進場成本價
                self.position = 1
                reward = 0.01  # 給予微幅探索正向獎勵，鼓勵合理進場
            else:
                reward = -0.02  # [懲罰] 已有部位卻重複買進，屬於無效動作

        elif action == 2:  # 動作 2：賣出 (SELL)
            if self.position == 1:
                # 計算扣除 0.4% 手續費與證交稅後的實際入帳現金與已實現報酬率
                net_proceeds = self.shares * current_price * (1.0 - self.fee_rate)
                realized_return = (current_price - self.entry_price) / self.entry_price - self.fee_rate
                self.cash = net_proceeds
                self.shares = 0.0
                self.entry_price = 0.0
                self.position = 0
                reward = realized_return * 100.0  # 放大成百分比點數，讓 PPO 梯度訊號更明確
            else:
                reward = -0.02  # [懲罰] 空手狀態卻執行賣出，屬於無效動作

        elif action == 0:  # 動作 0：持有/觀望 (HOLD)
            # 若持倉中，給予當日未實現漲跌幅的微幅回饋；空手觀望則獎勵為 0
            reward = daily_raw_ret * 10.0 if self.position == 1 else 0.0

        # 更新當日總資產淨值 = 現金 + 持股現值
        self.total_asset = self.cash + self.shares * current_price
        self.current_step += 1
        terminated = self.current_step >= len(self.df) - 1  # 走到最後一筆資料則結束回合
        return self._get_observation(), float(reward), terminated, False, {
            "total_asset": self.total_asset,
            "price": current_price,
            "position": self.position,
            "date": str(self.df.loc[self.current_step - 1, "Date"])[:10],
        }

# ==============================================================================
# 步驟 2：初始化並訓練 PPO 模型
# ==============================================================================
# [參數技巧] 1 個月資料約 18 筆，因此將 n_steps 調小為 64 (預設 2048 太大)
# 讓 PPO 在 5,000 步內就能完成數十次策略權重更新，且在 Colab CPU 數秒內完訓
model = PPO(
    policy="MlpPolicy",
    env=env,
    learning_rate=3e-4,
    n_steps=64,
    batch_size=32,
    verbose=0,
    seed=42,
)

# ==============================================================================

terminated = False
action_map = {0: "HOLD (觀望/續抱)", 1: "BUY (買進)", 2: "SELL (賣出)"}
trade_logs = []
closed_trade_rewards = []  # 僅紀錄「有效賣出平倉」的損益獎勵，用於計算勝率

    action, _ = model.predict(obs, deterministic=True)
    act_code = int(action)
    obs, reward, terminated, truncated, info = env.step(act_code)

    # 若為有效賣出平倉 (非 -0.02 無效懲罰)，收集該筆交易報酬
    if act_code == 2 and reward != -0.02:
        closed_trade_rewards.append(reward)

    trade_logs.append({
        "日期 (Date)": info["date"],
        "收盤價 (Close)": round(info["price"], 2),
        "決策動作 (Action)": action_map[act_code],
        "持倉 (Pos)": info["position"],
        "獎勵 (Reward)": round(reward, 4),
        "總資產 (Total Asset)": round(info["total_asset"], 2),
    })

# ==============================================================================

daily_rets = pd.Series(assets).pct_change().dropna()
final_asset = assets[-1]

# 1. PPO 累積報酬率 vs 買進持有基準 (Buy & Hold) 與超額報酬 (Alpha)
cum_ret = (final_asset - env.initial_balance) / env.initial_balance * 100
buy_hold_ret = (data["Close"].iloc[-2] - data["Close"].iloc[0]) / data["Close"].iloc[0] * 100
excess_alpha = cum_ret - buy_hold_ret

# 2. 年化夏普比率 (Sharpe Ratio)：衡量每承擔 1 單位風險所換取的超額報酬
sharpe_ratio = (daily_rets.mean() / (daily_rets.std() + 1e-8)) * np.sqrt(252) if len(daily_rets) > 1 else 0.0

running_max = np.maximum.accumulate(assets)
drawdowns = (assets - running_max) / running_max * 100
max_drawdown = float(drawdowns.min())

# 4. 平倉勝率 (Win Rate %)：獲利賣出次數 / 總有效賣出次數
win_trades = sum(1 for r in closed_trade_rewards if r > 0)
total_closed = len(closed_trade_rewards)
win_rate = (win_trades / total_closed * 100) if total_closed > 0 else 0.0

# 5. 綜合好壞自動判讀
if excess_alpha > 0 and sharpe_ratio >= 1.0 and max_drawdown > -10.0:
    verdict = "PASS (優於基準：風險報酬比佳)"
elif cum_ret > 0:
    verdict = "WARNING (正報酬但樣本短，建議拉長期間至 1y)"
else:
    verdict = "FAIL (報酬落後或過度交易，需調整獎勵函數)"

import numpy as np
from fastapi import FastAPI
from pydantic import BaseModel, Field
from stable_baselines3 import PPO

# ==============================================================================
# 步驟 1：初始化 FastAPI 服務並在啟動時預載訓練好的 PPO 模型
# ==============================================================================
app = FastAPI(
    title="聯發科 (2454.TW) RL 交易決策 API",
    description="接收即時標準化市場狀態向量，回傳 PPO 最佳交易動作",
    version="1.0.0",
)

# 在模組載入時直接將 .zip 權重讀入記憶體 (RAM)，避免每次請求都重新讀檔造成延遲
model = PPO.load("2454_ppo_trader.zip")

# 動作代碼與中英文交易建議對照字典
ACTION_MAPPING = {
    0: "HOLD (觀望/續抱)",
    1: "BUY (買進訊號)",
    2: "SELL (賣出平倉)",
}

# ==============================================================================
# 步驟 2：定義 Pydantic 資料驗證模型 (嚴格防呆輸入型別與範圍)
# ==============================================================================
class MarketState(BaseModel):
    # ge=0, le=1 確保持倉狀態只能是 0 或 1，若傳入其他數字 FastAPI 會自動回傳 422 錯誤
    has_position: int = Field(..., ge=0, le=1, description="當前持倉狀態 (0 或 1)")
    daily_return: float = Field(..., description="Z-Score 標準化後報酬率")
    ma3_bias: float = Field(..., description="Z-Score 標準化後 MA3 乖離率")
    volume_change: float = Field(..., description="Z-Score 標準化後成交量變化率")

# ==============================================================================
# 步驟 3：建立 POST /predict/action 即時推論端點
# ==============================================================================
@app.post("/predict/action")
def predict_action(state: MarketState):
    # 必須依照與 StockTradingEnv 完全相同的特徵順序組成 float32 向量
    obs = np.array([
        float(state.has_position),
        state.daily_return,
        state.ma3_bias,
        state.volume_change,
    ], dtype=np.float32)

    # [關鍵] 線上推論必須設定 deterministic=True，確保輸出穩定不隨機跳動
    action, _ = model.predict(obs, deterministic=True)
    code = int(action)

    return {
        "action_code": code,
        "recommended_action": ACTION_MAPPING[code],
    }

💡 什麼是 .zip (SB3 模型封裝檔)？為什麼不用 CSV 或 JSON 存模型？

        

          在強化學習中，訓練好的 PPO 模型包含 Actor（策略網路） 與 Critic（價值網路） 的多層 PyTorch 權重矩陣，以及環境的觀察空間 Box(4,) 與動作空間 Discrete(3) 定義。這些複雜物件只存在記憶體（RAM）裡，一旦 Colab 斷線就會歸零。透過 model.save("2454_ppo_trader")，Stable-Baselines3 會將網路權重與環境規格打包為高效率的 .zip 二進位封裝檔，讓 FastAPI 啟動時能用 PPO.load() 在幾毫秒內完整還原大腦，無需每次重新訓練 5,000 步。

            約 120 KB ~ 300 KB

• policy.pth           : Actor-Critic 雙層 MLP 神經網路的 PyTorch 權重張量

• observation_space    : Box(-inf, +inf, shape=(4,), dtype=float32)
• action_space         : Discrete(3)  # 0=HOLD, 1=BUY, 2=SELL

          


          

            
3. 為什麼要把觀察空間與模型打包在一起？

        強化學習演算法核心原理
        
9. PPO（Proximal Policy Optimization）：近端策略優化圖文深度解析與模擬

        

          為什麼金融強化學習首選 PPO？因為股市充滿雜訊，若模型因單日暴漲暴跌而大幅修改參數，策略很容易崩壞；PPO 透過 Actor-Critic 雙網路 與 Clip 信任域保護，讓交易策略在穩定中持續進化。
        

      


      
      

        
      


      
      

        

          
STEP 1 • 軌跡收集 (Rollout)

          
在環境中試錯累積經驗

          
每收集 n_steps=64 天的模擬交易紀錄（包含狀態、動作與扣稅後獎勵），才進行一次批次學習。

        

        

          
STEP 2 • 優勢評估 (Advantage)

          
這筆買賣比預期好多少？

          
若賣出後實際獲利高於 Critic 預期（A_t > 0），就提高該動作機率；若無效賣出被扣 -0.02（A_t < 0），就降低機率。

        

        

          
STEP 3 • 剪裁更新 (Clipped Update)

          
小步快跑、避免過擬合

          
透過 clip(r_t, 0.8, 1.2) 鎖住單次更新上限，像老練的操盤手一樣逐步微調進出場紀律。

        

      


      

        
PPO 剪裁目標函數 (Clipped Surrogate Objective)

        

          L^CLIP(θ) = E[ min( r_t(θ) * A_t , clip(r_t(θ), 1-ε, 1+ε) * A_t ) ]
        

      


      
      

        

          
PPO 動作機率與 0.4% 稅費獎勵即時換算面板

          

            
            
            
          

        

        

      


      
      

        

          
            

              PPO 超參數 (Hyperparameter)
              本案設定值
              量化交易工程意義 (Engineering Rationale)
            

          
          
            
policy"MlpPolicy"使用多層感知器處理 4 維表格型市場狀態向量。

            
n_steps64因應 1 個月僅約 18–20 個交易日，調小步數以增加梯度更新頻率。

            
batch_size32每次小批次抽樣 32 筆經驗更新網路權重，兼顧速度與穩定度。

            
learning_rate3e-4Adam 優化器學習率，確保在 5,000 步內平穩收斂不震盪。

            
total_timesteps5000在 Google Colab CPU 上僅需數秒即可完成訓練。
