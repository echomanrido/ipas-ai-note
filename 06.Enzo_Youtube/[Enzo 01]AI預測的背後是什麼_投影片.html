AI 預測的背後是什麼？
不是玄學，是數學與調旋鈕

從解鎖手機、垃圾信件攔截到 YouTube 推薦，機器每天都在為你服務。
但機器到底在學什麼？怎麼學？學完怎麼知道有學會？

1

機器到底在學什麼？

顛覆傳統邏輯，尋找那個神奇映射函數 $y = f(x)$。

2

機器是怎麼學習的？

用損失函數給自己打分數，濃霧中靠梯度下降摸黑下山。

3

如何證明真的學會？

避開死背考題的 Overfitting，切分三套試卷驗證真才實學。

The Paradigm Shift

傳統程式設計 vs 機器學習

「寫一隻程式判斷照片有沒有貓？世界太複雜，你寫不完所有規則！」

傳統程式設計 (Rule-Based) 人寫規則

// 試圖枚舉全世界所有的條件

if (hasPointyEars && hasWhiskers) {

return "Cat";

} else if (isFluffy && walksOnPaws) { ... }

// 永遠防不勝防的邊界情況 (折耳、毛色、角度)

規則 Rules + 資料 Data ➜ 答案 Output
痛點：人類經驗有限，無法應付高維度多元複雜世界。
機器學習 (Machine Learning) 機器找規則
1 給電腦幾萬張照片（輸入 $X$）
2 給對應解答「是貓 / 不是貓」（答案 $Y$）
3 讓演算法自行逆推尋找映射關係 $y = f(x)$
資料 Data + 答案 Answers ➜ 規則 Model / Rules
優勢：從海量高維特徵中自行提取人類難以言傳的規律。
Core Analogy

所有機器學習，都是在「調混音器旋鈕」

公式核心：$y = f(x; W)$
Neural / Parametric Mixer Console
4 Parameters Active
$w_1$ (權重 1) 耳朵尖銳度
$w_2$ (權重 2) 毛皮紋理特徵
$w_3$ (權重 3) 鬍鬚對比度
$b$ (偏差值) 基礎背景門檻
輸出誤差與目標音準比對： Accuracy: 94.2%

旋鈕 = 參數 (Parameters)

一開始隨機亂轉，輸出當然亂七八糟。「訓練」就是根據預測好壞，不斷微調這幾千、幾億個旋鈕。

從幾顆旋鈕到千億旋鈕

小模型（如線性回歸）只有 2~3 個旋鈕；GPT-4 等大型語言模型有超過上萬億個旋鈕。本質完全相同，差別只在於混音器架構與微調演算法。

關鍵在於：手頭上有什麼資料，決定了你該用哪種方法去調這些旋鈕！
The 3 Paradigms

機器學習的三大主流門派

依據資料型態與回饋機制，決定機器如何探索規律

門派 01

監督式學習

Supervised Learning

「附詳解的考古題」
每題都附有標準答案（標籤 Label）。算錯就立刻調旋鈕。

分類 (Classification) 類別答案：貓/狗、垃圾信
回歸 (Regression) 連續數值：房價、氣溫
代價：需要大量昂貴的人力標註（如自駕車標註行人）。
門派 02

非監督式學習

Unsupervised Learning

「倒在床上的衣服堆」
沒人教名字，你自己把褲子放一堆、T-shirt 放一堆，發現特徵相似。

分群 (Clustering)
把特徵相鄰的聚合在一起
自駕車光達 (LiDAR)
每秒數十萬無標籤 3D 點雲聚成障礙物
亮點：不需要昂貴標註，專注發掘資料深層幾何與分佈。
門派 03

強化學習

Reinforcement Learning

「訓練小狗握手給肉乾」
不給講義，讓代理人嘗試動作；做對給獎勵、做錯扣分，自尋策略。

試錯演進 (Trial & Error)
AlphaGo 下圍棋、機器人學倒立與奔跑
賽車最佳過彎線
在模擬器跑數百萬次探尋極限操作
挑戰：極度依賴大量試錯（幾百萬次），需在模擬環境中訓練。
Step 1: Quantify Errors

怎麼知道模型有多爛？損失函數 (Loss Function)

給模型打一個「不及格分數」，目標是讓這個數字壓到最低

經典指標：均方誤差 (MSE)
$$\text{Loss (MSE)} = \frac{1}{N} \sum_{i=1}^{N} (y_i - \hat{y}_i)^2$$
$y_i$：真實答案（例如真實房價 1000 萬）
$\hat{y}_i$：模型猜測（例如預測 800 萬）
誤差：$1000 - 800 = 200$ 萬

為什麼一定要「平方」？兩大核心原因

01

消除正負正負相互抵消

猜高 (+200 萬) 與猜低 (-200 萬) 都叫作「猜錯」。若直接相加總和變 0，模型會誤以為自己完美無缺。平方確保所有誤差皆為正數！

02

嚴厲放大嚴重錯誤

差 10 萬平方是 $100$；但差 100 萬平方就暴增為 $10,000$！模型會對離譜的猜測產生巨大懲罰，因而強烈避免大錯。

目標轉換為純數學問題：尋找一組旋鈕，使 $\text{Loss} \to \min$
Step 2: Optimization

梯度下降：在大霧中摸索下山的路

不盲目窮舉百萬個旋鈕，靠微分指引最佳下切角度

更新公式：$W_{\text{new}} = W_{\text{old}} - \eta \cdot \nabla \text{Loss}$
1. 山的高度 ➜ Loss 損失

目前模型的預測到底有多差。

2. 站立位置 ➜ 旋鈕參數 $W$

目前這組權重設定所處的狀態。

3. 腳下坡度 ➜ 梯度 $\nabla$ (微分)

微分一次，就能直接指出「所有旋鈕」該往哪邊調才能最快下山！不用盲猜 100 萬次。

公式中的負號：因為梯度指向上坡，我們必須向反方向（下坡）走！
Step 3: Step Size

每一步要跨多大？學習率（$\eta$）的生死抉擇

整個機器學習最讓人抓狂、最關鍵的超參數設定

步幅過小 Too Small

一步一公分，走到天亮

方向完全正確，但運算時間極為昂貴。電腦跑了三天三夜，進度條只走 5%。

後果：收斂龜速、耗盡算力
步幅過大 Too Large

左右橫跳，甚至原地爆炸

一步直接跨過谷底飛到對面山頭，甚至越跳越高，導致 Loss 數值無限發散（NaN 爆炸）。

後果：模型發散、梯度爆炸
剛剛好 Just Right

穩步下滑抵達谷底

步幅適中，能在合適迭代次數內平滑收斂至最佳損失值。

注意「局部最小值 (Local Minimum)」陷阱：半山腰的小水坑。
Generalization vs Overfitting

Loss 降到 0 就完美了？致命的危險訊號！

一個班上有三個學生在準備期末考...

A

學生 A：完全沒讀書

欠擬合 Underfitting

考古題寫得一塌糊塗，期末考當然也直接爆掉。模型過於簡單，連基本規律都抓不到。

考古題: 40分 期末考: 30分
B

學生 B：死背考古題

過擬合 Overfitting (大忌！)

把考古題第3題選C、第7題答案42全部死背下來。考古題 100 分，期末考換個數字立刻交白卷！把雜訊巧合當成了規律。

考古題: 100分 期末考: 20分
C

學生 C：理解核心觀念

泛化能力 Generalization

不追求考古題 100 分，而是領會公式與題意本質。遇到全新題型依然能冷靜推理拿高分。

考古題: 90分 期末考: 88分
機器學習真正的目標，從來不是把訓練資料學到完美，而是「在沒看過的資料上也對」！
Evaluation & Pitfalls

如何抓出作弊？資料的三切法與致命陷阱

絕不能用學過的資料考模型，否則你永遠不知道它在死背

原始全部資料 (100%) 三套獨立考卷
訓練集 Training Set (60~70%)
驗證集 Val (15~20%)
測試集 Test (15~20%)
考古題：訓練集 模型拿來看題、算微分、調動旋鈕參數。
模擬考：驗證集 決定學習率該多大、模型該多深多複雜。
期末考：測試集 鎖在保險箱，整個專案最後只評測一次！
陷阱一：資料洩漏 (Data Leakage)

期末考題不小心混入考古題！例如：同一個行人的連續影片，第 1 秒在訓練集、第 2 秒跑去測試集。模型看似滿分，一上路就車禍。

陷阱二：分佈偏移 (Distribution Shift)

自駕車只在天天大晴天的亞利桑那州訓練與測試，分數極佳；但開到暴風雪的城市立刻傻眼癱瘓。真實世界永遠比資料集大！
