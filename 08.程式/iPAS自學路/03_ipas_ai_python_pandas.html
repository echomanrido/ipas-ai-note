UNIT 01

參數順序的絕對鐵律：位置在前，名稱在後

藍框核心：定義與呼叫的兩大鐵則
  • ① 宣告時： 有預設值的參數（Default Arg）必須放在無預設值的位置參數之後。
  • ② 呼叫時： 位置參數永遠必須在關鍵字參數之前！一旦開始使用 key=val 呼叫，後方就絕對不能再出現位置參數。
# 正確合法範例
def calc_bonus(salary, rate=0.1):
    return salary * (1 + rate)

calc_bonus(50000, rate=0.15) # ✅ PASS
紅框警告：考卷中最愛的 SyntaxError

為什麼顛倒會報錯？因為 Python 直譯器由左至右解析時，若先遇到關鍵字或預設值，後續的位置參數將無法精準對應到變數槽位！

# 陷阱1：定義時預設參數在先
def bad_func(a=1, b): # ❌ SyntaxError
# non-default argument follows default argument
# 陷阱2：呼叫時位置參數落後
good_func(a=10, 20) # ❌ SyntaxError
# positional argument follows keyword argument

UNIT 02

變數領地（Scope）與 Global 神聖指令

綠框安全：變數的生老病死與「結界保護機制」
LEGB 作用域原則

在函式內部直接宣告或指派 level = 99，Python 預設會啟動安全結界，在該函式的呼叫堆疊（Stack Frame）中建立一個全新的區域變數（Local Variable）。當函式執行結束，此結界立刻隨記憶體釋放灰飛煙滅，全域環境中的本尊毫髮無傷！

🛡️ 無 global（安全結界）：

函式內的改動只活在函式裡，同名變數只是替身，外部全域變數依然保留原值。

⚡ 有 global（直接穿透）：

明令直譯器「直搗黃龍」，將賦值權限直接套用至最外層全域記憶體，覆蓋原值。

記憶體穿透模擬器：宣告 vs 未宣告 global

切換開關，觀察資料流指派指針如何影響不同記憶體空間

level = 10 # 全域變數


def level_up():

# 尚未宣告 global

level = 99 # 賦值動作


level_up()

UNIT 03

防禦裝甲：try-except-else-finally 拆彈部隊

橘框防禦：四大區塊職責分工與執行特權
try :

防護力場。將帶有未爆彈或潛在錯誤的危險程式碼封裝在內。

except Type:

拆彈工兵。只攔截符合型態的炸彈；未符合則繼續向外拋出。

else :

安全綠燈。僅在 try 內無任何錯誤時，才會執行的乾淨流程。

finally :

最高霸權！不論成功、失敗、中途出錯，甚至是遇到 return，都必定執行！

iPAS 實戰邏輯測驗機（原創經典真題）

QUESTION 01・例外類型匹配與 Finally 權限 ★ iPAS 命中率 99%

閱讀以下 Python 程式碼，請問執行後終端機印出的完整內容為何？ 

def quiz_exam():
    try:
        x = int("xyz")     # 將英文字串轉為整數
        return 1
    except TypeError:
        return 2
    except:
        return 3
    finally:
        print("CleanUp", end="-")

result = quiz_exam()
print(result)
QUESTION 02・參數順序與 SyntaxError 陷阱 ★ 必考觀念題

已知函式定義為 def calc(a, b=5, c=10): return a + b + c，下列哪一種呼叫方式在直譯時會直接引發 SyntaxError 語法錯誤？

考前 30 秒口訣速記錦囊（進考場前必背）

口訣 1：位前名後不可逆

宣告時：位置在先、預設在後；
呼叫時：位置在先、關鍵字在後。
只要看到 f(a=1, 2) 一秒判定 SyntaxError。

口訣 2：不見 Global 原樣回

考題只要考「函式內改了全域變數」，先用肉眼掃描有無 global。
沒寫 global，外面的值就永遠不會變！

口訣 3：Finally 奉陪到底先插隊

不管 try 裡有多霸道的 return，都必須被暫停，乖乖等待 finally 區塊執行完畢後才正式回傳。

陷阱一拆解：def 宣告時的預設參數鐵律

⚠️ 紅框死穴：SyntaxError 殺手題

「首先第一個鐵律：在 def 定義函式時，有給預設值的參數，絕對、必須排在沒有預設值的位置參數後面！如果你寫成 def func(a=1, b):，直譯器一看到就直接報出 SyntaxError: non-default argument follows default argument。為什麼？因為電腦根本無法判斷你傳入的第一個值到底是要給 a 還是給 b！」

❌ 違規寫法： def create_user(role="guest", username): pass
✅ 正確寫法： def create_user(username, role="guest"): pass

🛡️ 橘框架構：四大區塊職責

「第三個陷阱是例外處理的四大金剛：try、except、else 與 finally。try 放可能有未爆彈的程式碼；except 是拆彈防暴組，捕捉特定的錯誤；而 else 非常高冷，只有在 try 區塊完全順利、沒有任何一點錯誤的情況下才會執行；最後則是無論如何都會壓軸登場的 finally。」

00:05:59 - 00:06:53

finally 的終極霸權：連 return 都要靠邊站

⚡ 橘框核心：最高優先級規則

「請大家在筆記本上打三顆星！finally 擁有 Python 中的最高執行特權。很多考題故意在 try 或 except 區塊裡面寫 return 100。很多同學就以為程式直接回傳結束了。錯！就算遇到了 return 指令，Python 也會立刻按下暫停鍵，強迫插隊把 finally 區塊裡的每一行都執行完，才會放行回傳！」

🚨 考場致命陷阱： 若 finally 區塊內自己也包含 return 999，它甚至會無情覆蓋掉 try 區塊原本準備要 return 的數值！
