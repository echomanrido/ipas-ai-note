Python 核心：逐行直譯（由上而下，絕不預警）

直譯器就像死板的口譯官，讀一行、做一行

核心本質：直譯式語言 (Interpreted)

不同於 C/C++ 會在執行前做編譯期全檔語法檢查，Python 直譯器遵循「由上而下、一次一行」。在執行到錯誤行之前，前置程式碼皆會如常執行輸出。

考場經典陷阱

若題目中第 10 行存在致命錯誤（例如語法有誤或除以零），第 1 到 9 行的輸出仍然會被列印出來，到了第 10 行才拋出異常中斷，絕不會預先警告！

等號的本質：賦值命令（=）與條件問答（==）

左邊是容器，右邊是數值；方向不可逆轉

= 賦值（命令句）

方向由右向左：x = 10 意思是「命令把數值 10 塞進變數 x 盒子中」。

== 比較（疑問句）

詢問兩側是否等值：x == 10 是在問「x 現在等於 10 嗎？」，回傳 True 或 False。

致命非法寫法

常考陷阱 1：10 = x（數值不可作為左值，報錯！）
常考陷阱 2：if x = 10:（條件式塞入命令句，SyntaxError！）

互動模擬：點擊切換模式查看直譯器解析視角

[ 賦值指令 ] 把右邊的 10 指派給左邊的變數 x 儲存空間。

縮排（Indentation）不是排版美學，而是語法法律

不用大括號 {}，空格決定了程式碼的管轄歸屬

層級管轄關係

縮排進去一級，就代表被上層條件管轄。
最外層無縮排的陳述式：誰都管不到它，無論前面條件成不成立，直譯器最後都必定執行！

考場大送分題：IndentationError

考題若給出一段排版錯亂的程式碼，同一層級的陳述式空格數不同（如一行退 4 格、下一行退 5 格），想都不用想，直接勾選「無法執行，語法報錯」！

NESTED SCOPE VISUALIZER (管轄作用域視覺化) 點擊不同行標示管轄範圍
Line 1: if is_system_on:
Line 2: check_battery() 受 Line 1 管轄 (縮排 4 格)
Line 3: if battery < 20: 受 Line 1 管轄
Line 4: alert("LOW POWER!") 雙重條件約束 (縮排 8 格)
Line 5: print("Process Finished") 最外層：不受任何條件限制

影片結尾任務解答：逐一處理 data = [1, 2] 該用 if 還是 for？

兩者在根本邏輯上的本質差異與底層機制

if (條件分支 Branching)

只做 0 或 1 次

if 是一個「分岔路口」。它只會對傳入的條件做單一次真假判斷（True 走這條路，False 繞過或走 else）。它不具備重複迭代機制，不能直接用來遍歷容器中每個元素。

# if 只是判斷容器是否有東西，不會逐一拿取
if data:
    print("容器不是空的") # 僅執行一次

for (迭代迴圈 Iteration)

正確解答：逐一巡訪

for 專門用來處理可迭代物件（Iterable）。它會在底層建立迭代器，依序將元素從容器中取出，賦值給臨時變數，並重複執行區塊直到容器耗盡。

# for 會依序拿出 1，再拿出 2
for item in data:
    print(item) # 依序印出 1 與 2

觀念總結心法

想「過濾／檢查條件」選 if；想「走訪所有清單項目」選 for。實務上常常合體為：for item in data: if item > 1: ...（邊遍歷邊判斷）。

型態碰撞炸彈：print(10 + "10") 與強型別原則

必出高頻題

【原音逐字】「現在來一題經典的陷阱暖身一下。畫面上這一行 print(10 + "10")，你覺得會印出什麼？給你三秒鐘想一下：是 20 嗎？還是 1010？還是會發生別的事？答案揭曉：都不是！程式會直接給你一個大大的 TypeError 直接罷工！為什麼？因為 Python 是一種強型別語言，意思就是它很龜毛、很有原則。數字就是數字，文字就是文字，你不能把這兩個完全不同的物種直接相加！這就像你不能把一顆蘋果跟一個香蕉加在一起，是完全沒道理的。那到底要怎麼做才對？很簡單，你有兩條路可以選：
第一，走數學的路：10 + int("10") 得到數字 20。
第二，走文字的路：str(10) + "10"，把兩個字串黏在一起，得到文字 "1010"。
想在中間不做任何轉換就混用？門都沒有！」

路線 A（轉型數字算術）：
10 + int("10") ➔ 20 (int)
路線 B（轉型字串拼接）：
str(10) + "10" ➔ "1010" (str)

IndentationError

【原音逐字】「接下來這一點，你給我聽好了：這在 Python 的世界裡不是什麼美學建議，它就是法律！這個東西叫做縮排，也就是程式碼前面的空格。在別的程式語言可能會用大括號來分區塊，但在 Python 空格就是一切！你看這個例子：check_battery 前面有縮排，代表它被關在 if is_system_on 的管轄範圍內；然後 alert 又往內縮了一層，代表它更可憐，必須要 system_on 跟 battery < 20 同時成立，它才能被執行。那最後的 print end 呢？它沒有縮排，自己站在最外面，代表他誰都不管，不管前面發生什麼事，程式跑到最後就一定會執行它！這就帶來了一個超愛考的送分題——IndentationError。如果題目給你一段亂七八糟的程式碼，你只要看到明明應該在同一個層級的指令，他們的縮排空格數不一樣，比如說一個空了四格、一個空了五格，那你連想都不用想，直接選『程式無法執行』！這不是邏輯問題，這是語法上的死刑！」
