01

StandardScaler() —— Z-score 標準化 特徵縮放

sklearn.preprocessing.StandardScaler
真題對位：114-2 Q9 / 核心鐵律 C11
費曼白話直覺：「全班成績標準化」

不管各科滿分是 100 還是 1000，通通換算成「全班平均 0 分、標準差 1 分」，讓身高（公分）和體重（公斤）可以在同一個起跑線上被公平計算。

距離與協方差敏感演算法之「特徵縮放鐵律」

數理公理：凡是以「歐氏距離」或「協方差矩陣變異數」為計算核心的模型，若特徵數值範圍差異過大，大尺度特徵將 100% 主導計算結果，造成空間嚴重扭曲！

① KNN（K 近鄰）： 歐氏距離計算，未縮放時年薪（數十萬）會徹底淹沒年齡（數十歲）。
② SVM（支援向量機）： 幾何邊界間隔與 RBF 核函數均嚴格依賴特徵點之間的歐氏距離。
③ K-Means（K 均值分群）： 質心歐氏距離計算，未縮放導致分群沿大尺度軸拉成畸形長條。
④ PCA（主成分分析）： 依方差大小尋找投影軸，未縮放時數值大的特徵人為虛增方差，霸佔第一主成分！
唯一例外豁免（超常考！真題 SIM-L23301-003）： 樹系模型（Decision Tree, Random Forest, GBDT, XGBoost）「完全不需要特徵縮放」！因為樹模型僅做單一維度的單調閾值切分（如 \(x > 50\)），數值縮放絲毫不改變切分點的相對排名順序！
黃金實踐程式碼：StandardScaler 與 Pipeline 杜絕洩漏 
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.neighbors import KNeighborsClassifier

# 最佳實踐：將特徵縮放與距離敏感模型封裝入 Pipeline，徹底杜絕洩漏並對齊尺度
pipeline = make_pipeline(
    StandardScaler(),
    KNeighborsClassifier(n_neighbors=5)
)
pipeline.fit(X_train, y_train)
accuracy = pipeline.score(X_test, y_test)

逐行解構與設計動機（底層科學機制剖析）

  • make_pipeline(...)：自動將資料前處理器與模型捆綁成單一自動化管線，依序命名為 standardscaler 與 kneighborsclassifier。
  • pipeline.fit(X_train, y_train) 底層三部曲：

    • 步驟 1（校正基準尺規）：標準化器掃描訓練資料，量出每個特徵的「中心基準（平均值 \(\mu\)）」與「分散寬度（標準差 \(\sigma\)）」，並永久鎖定儲存於物件屬性 scaler.mean_ 與 scaler.scale_ 中。

    • 步驟 2（資料平移縮放）：用這把鎖定尺規，將訓練特徵全部轉換成「以 0 為基準、分散度統一為 1」的無量綱數值陣列。

    • 步驟 3（建立空間索引）：將轉換後的公平特徵傳入 KNN，KNN 在無尺度偏差的空間中建立近鄰索引。

  • pipeline.score(X_test, y_test)：內部自動呼叫 scaler.transform(X_test)，套用訓練集的尺規轉換測試集，絕不重新計算測試集的均值，杜絕前視洩漏！
順序反轉因果對比（反事實推導）
  • 反事實陷阱 1（在 train_test_split 前做 fit_transform）： 測試集的資訊（未來均值與方差）被融入尺規中，產生致命的「資料洩漏（Data Leakage）」，線下評估虛高 10%~20%，線上部署瞬間雪崩！
  • 反事實陷阱 2（測試集呼叫了 scaler.fit_transform(X_test)）： 測試集被迫採用自己的均值與標準差，等於考試時偷偷篡改了計分標準，破壞了「訓練集與測試集獨立同分佈（i.i.d.）」的統計學公理！
核心考點與誘餌選項排雷（iPAS 題眼秒殺）

• 題目看到「距離敏感模型」+「特徵尺度相差懸殊」：直覺必配 StandardScaler！

• 誘餌選項 (A)「決策樹模型必須先做標準化才能防止過擬合」：❌ 樹模型對單調變換完全免疫，無需特徵縮放！

• 誘餌選項 (B)「測試集特徵應單獨 fit_transform 獲得最佳表現」：❌ 致命錯誤！測試集只能使用 transform()！

最小可執行單元測試契約 (Google Colab / 本機驗證) 
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.neighbors import KNeighborsClassifier

def test_pipeline_leakage_prevention() -> None:
    X_train = np.array([[1.0, 100.0], [2.0, 200.0], [3.0, 300.0]])
    y_train = np.array([0, 0, 1])
    X_test = np.array([[10.0, 1000.0]])
    y_test = np.array([1])
    
    pipeline = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=1))
    pipeline.fit(X_train, y_train)
    
    # 斷言：Pipeline 內部 scaler 僅保存訓練集統計量，且測試集轉換保持一致
    scaler_step = pipeline.named_steps['standardscaler']
    np.testing.assert_allclose(scaler_step.mean_, [2.0, 200.0])
    pred = pipeline.predict(X_test)
    assert pred.shape == (1,), "預測維度契約不合"
    assert pred[0] == 1, "KNN 距離分類結果偏離"
02

SMOTE() —— 合成少數類過採樣 樣本平衡

imblearn.over_sampling.SMOTE
真題對位：114-2 Q35 / 115-1 Q35
費曼白話直覺：「珍稀標本的連線塑形法」

如果博物館裡暴龍化石只有 2 隻，隨機過採樣（Random Oversampling）就像影印 100 張一模一樣的照片，模型只會死背這兩隻化石的細節（過擬合）；而 SMOTE 則是在兩隻暴龍的特徵骨架之間拉出線段，在線段上隨機生成全新、合理的「合成暴龍」，既補齊數量，又擴大泛化邊界！

黃金實踐程式碼：SMOTE 僅在訓練集過採樣 
from imblearn.over_sampling import SMOTE
from collections import Counter

# 核心鐵律：僅在訓練集上過採樣，測試集必須保持原始真實母體分佈！
smote = SMOTE(sampling_strategy='auto', random_state=42)
X_train_res, y_train_res = smote.fit_resample(X_train, y_train)

print("原始訓練集分佈:", Counter(y_train))
print("過採樣後分佈:", Counter(y_train_res))

逐行解構與設計動機（底層科學機制剖析）

  • sampling_strategy='auto'：將少數類樣本數直接補齊至與多數類樣本數 1:1 完全相等。
  • fit_resample(...) 底層數學三步曲：

    • 步驟 1（KNN 尋鄰）：對每個少數類樣本 \(x_i\)，在特徵空間中尋找其同類最近的 \(k\) 個近鄰（預設 \(k=5\)）。

    • 步驟 2（隨機連線）：隨機挑選其中一個鄰居 \(x_{zi}\)，在兩點之間構建連線向量：\(\Delta = x_{zi} - x_i\)。

    • 步驟 3（線性插值）：在 \([0, 1]\) 區間隨機採樣一個權重 \(\lambda\)，生成全新合成樣本：\(x_{new} = x_i + \lambda \cdot (x_{zi} - x_i)\)。

順序反轉因果對比（反事實推導）
  • 反事實災難（對全資料集或測試集做 SMOTE）： 合成樣本同時出現在訓練集與測試集之間（互相插值），測試集遭到人為污染，線上模型面對真實世界的極端失衡分佈時完全失去識別能力，產生巨大漏報！
核心考點與誘餌選項排雷（iPAS 題眼秒殺）

• 題目看到「信用卡盜刷 / 罕見疾病分類」+「正負樣本比 1:99」：秒選 SMOTE！

• 題眼陷阱：「SMOTE 是透過複製貼上少數類樣本嗎？」❌ 錯！那是 Random Oversampling，SMOTE 是透過 KNN 線性插值合成全新樣本！

最小可執行單元測試契約 (Google Colab / 本機驗證) 
import numpy as np
from imblearn.over_sampling import SMOTE
from collections import Counter

def test_smote_balance_contract() -> None:
    # 構造極度不平衡資料 (10 個類別 0, 2 個類別 1)
    X = np.random.randn(12, 4)
    y = np.array([0]*10 + [1]*2)
    
    # 由於少數類只有 2 個樣本，k_neighbors 設為 1
    smote = SMOTE(sampling_strategy='auto', k_neighbors=1, random_state=42)
    X_res, y_res = smote.fit_resample(X, y)
    
    counts = Counter(y_res)
    assert counts[0] == 10, "多數類樣本數異常受改動"
    assert counts[1] == 10, "少數類樣本數未精準補齊至 10"
    assert X_res.shape == (20, 4), "合成矩陣張量形狀契約失效"
【知識補充專題 1】特徵縮放四大天王評估矩陣 & 資料洩漏防禦策略

在實務與高階考題中，除了標準化之外，還常出現以下特徵縮放器的對比：

縮放器 (Scaler) 轉換公式 數值邊界 抗異常值 (Outliers) 能力 最佳適用場景
StandardScaler \(z = rac{x - \mu}{\sigma}\) \((-\infty, +\infty)\)，均值0方差1 弱（均值易被離群點拉偏） 多數常態分佈資料、PCA、SVM、KNN
MinMaxScaler \(x' = rac{x - x_{min}}{x_{max} - x_{min}}\) [0, 1] 嚴格有界 極弱（極端值直接霸佔 0 或 1） 影像像素 [0, 255] 歸一化、神經網絡輸入
RobustScaler \(x' = rac{x - Q_2}{IQR}\) 無嚴格邊界 極強（基於中位數與四分位差） 存在大量極端異常值/長尾分佈的特徵
Normalizer \(x' = rac{x}{\|x\|_p}\) (行向量歸一) 模長為 1 不適用（按樣本行計算） 文字 TF-IDF 向量、餘弦相似度 (Cosine) 計算

資料洩漏防禦三大守則： (1) 嚴格時序切分：若是金融交易或股價數據，禁止隨機抽樣，必須採用時間滾動切分（TimeSeriesSplit）防止前視偏差（Lookahead Bias）。 (2) 全管線化（Pipeline）：將 Imputer、Scaler、FeatureSelector 一律封裝入 Pipeline，確保任何操作都在交叉驗證的內部 Fold 執行！

PCA(n_components=...) —— 主成分分析（非監督降維之王）

sklearn.decomposition.PCA
真題對位：114-1 Q38 / 114-2 Q38
費曼白話直覺：「從最佳角度拍皮影戲」

一隻立體的 3D 茶壺，你要把它拍成 2D 影子照片，必須挑選能同時看清壺嘴和把手最寬闊的角度（最大變異數方向）。前面的主成分保留主幹幾何輪廓，後面微小的特徵值代表微弱隨機雜訊。

黃金實踐程式碼：StandardScaler + 自適應累積方差 PCA 
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

# 核心最佳實踐：特徵縮放 + PCA (保留 95% 累積解釋變異量)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)

pca = PCA(n_components=0.95, random_state=42)
X_train_pca = pca.fit_transform(X_train_scaled)

print("保留的主成分軸數:", pca.n_components_)
print("各主成分解釋變異比率:", pca.explained_variance_ratio_)
print("累積解釋變異比率:", pca.explained_variance_ratio_.sum())

逐行解構與設計動機（底層科學機制剖析）

  • PCA(n_components=0.95)：輸入浮點數（小數）0.95，代表「請演算法自適應挑選最少的主成分軸數，使整體保留的累積資訊變異比率達到 95% 以上」。若輸入整數（如 5），則代表強制降為 5 個主成分。
  • explained_variance_ratio_：輸出每個主成分所佔的變異數百分比，加總即為總解釋變異量。
順序反轉因果對比（反事實推導）
  • 反事實災難（不做特徵縮放直接跑 PCA）： PCA 盲目追求數值變異數最大化。如果特徵 A 的單位是公克（變異數數萬），特徵 B 的單位是公噸（變異數 0.01），特徵 A 會人為虛增方差，100% 霸佔第一主成分，使 PCA 降維徹底失去意義！
核心考點與誘餌選項排雷（iPAS 題眼秒殺）

• 題目看到「非監督式」+「最大化保留原始資料方差」+「消除特徵共線性」：秒選 PCA！

• 誘餌選項「PCA 降維時會利用樣本的標籤資訊來區分不同類別」：❌ 錯！PCA 是標準的「無監督（Unsupervised）」學習，絕不看標籤 \(y\)！要看標籤的是 LDA！

最小可執行單元測試契約 (Google Colab / 本機驗證) 
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

def test_pca_variance_threshold_contract() -> None:
    # 構造 5 維資料：前 2 維方差極大 (信號)，後 3 維方差極微 (雜訊)
    X_base = np.random.randn(80, 2) * 5.0
    X_noise = np.random.randn(80, 3) * 0.1
    X = np.hstack([X_base, X_noise])
    
    scaler = StandardScaler()
    X_scaled = scaler.fit_transform(X)
    
    pca = PCA(n_components=0.90, random_state=42)
    X_pca = pca.fit_transform(X_scaled)
    
    # 斷言：高方差信號應自適應降至約 2 維，且累積方差 >= 0.90
    assert pca.n_components_ <= 3, "PCA 未能有效消除微弱雜訊維度"
    assert pca.explained_variance_ratio_.sum() >= 0.90, "累積解釋變異比率未達標"
04

LinearDiscriminantAnalysis() —— LDA 監督式線性判別降維

sklearn.discriminant_analysis.LinearDiscriminantAnalysis
真題對位：115-1 Q44-45 (鳶尾花 3 類降維上限)
費曼白話直覺：「排隊分班站好」

# 鳶尾花有 3 個類別 (C=3)，LDA 最多只能降至 3 - 1 = 2 維！

逐行解構與設計動機（底層科學機制剖析）

  • lda.fit_transform(X_train, y_train)：必須同時傳入特徵與標籤 \(y\)，因為它是監督式（Supervised）降維。
  • 維度天花板數理根源： 類間散布矩陣 \(S_B = \sum_{c=1}^C N_c (\mu_c - \mu)(\mu_c - \mu)^T\)，由 \(C\) 個類別中心向量組成，其矩陣的秩（Rank）在數學上嚴格滿足： \[ ext{Rank}(S_B) \le C - 1\] 因此所能求解出的非零廣義特徵值最多只有 \(C - 1\) 個！若設定 \(n\_components \ge C\)，程式將直接拋出 ValueError 異常！
核心考點與誘餌選項排雷（iPAS 題眼秒殺）

• 題目問「鳶尾花資料集共有 3 個品種，請問 LDA 降維最多可保留幾個特徵維度？」：秒答 2 個（\(3 - 1 = 2\)）！

• 題目問「二元分類（2 個類別）問題，LDA 降維後的維度是多少？」：秒答 1 維（\(2 - 1 = 1\)）！

超重要！LogisticRegression 的超參數 \(C\) 與正則化強度呈現「嚴格倒數關係」！

\(C = rac{1}{\lambda}\) （\(C\) 越大，正則化懲罰越弱；\(C\) 越小，正則化約束越強）

情況二：模型嚴重過擬合 (Overfitting) 原因：權重膨脹。處置：調小 \(C\) 值（如 \(C=0.01\)），加強懲罰，強制把不重要的權重壓向 0！

Lasso(alpha=0.1) vs. Ridge(alpha=1.0) —— L1 與 L2 正則化

sklearn.linear_model.Lasso / Ridge
真題對位：114-1 Q15 / 114-2 Q15
費曼白話直覺：「大掃除 vs 全員均攤」

Lasso (L1) 是「鐵面無私大掃除」，約束幾何形狀是「尖銳菱形」，等高線極易撞在頂點上，把不重要的係數直接砍成精確的 0（特徵稀疏解）；
Ridge (L2) 是「全員均攤節能」，約束幾何形狀是「圓形」，等高線與圓周相切，係數平滑縮小但不為 0，專治特徵高度多重共線性！

from sklearn.linear_model import Lasso, Ridge

def test_l1_l2_sparsity_contrast() -> None:
    np.random.seed(42)
    X = np.random.randn(40, 8)
    y = 3.0 * X[:, 0] + np.random.randn(40) * 0.1 # 僅第 0 維是真實特徵

    assert not (ridge.coef_ == 0.0).any(), "Ridge 不應產生精確零係數"
【知識補充專題 4】幾何約束面解構 & ElasticNet 彈性網混合正則化

為什麼 L1 會產生 0 係數？
在二維空間中，L1 正則項 \(\|\mathbf{w}\|_1 \le C\) 的可行域是一個頂點在座標軸上的「正方形菱形」；而 L2 正則項 \(\|\mathbf{w}\|_2^2 \le C\) 是一個光滑的「圓形」。 損失函數的橢圓等高線向外擴展時，第一次接觸到菱形區域的點，極大概率落在「尖銳頂點（即 \(w_1=0\) 或 \(w_2=0\)，座標軸切點）」上；但接觸到圓形時，切點幾乎都是座標非零的光滑邊緣！

💡 延伸演算法：ElasticNet（彈性網） 當特徵維度 \(P \gg N\) 且特徵之間存在高度相關時，Lasso 往往只會隨機挑選其中一個特徵，將其他相關特徵粗暴歸零。 ElasticNet 同時加入 L1 與 L2 懲罰項： \[\mathcal{L} = ext{MSE} + r \cdot lpha \|\mathbf{w}\|_1 + rac{1-r}{2} \cdot lpha \|\mathbf{w}\|_2^2\] 既具備 Lasso 篩選特徵的稀疏性，又具備 Ridge 穩定均攤群組效應（Grouping Effect）的能力！

【知識補充專題 5】分群成效評估（無標籤情境）& 輪廓係數 (Silhouette Score)

在非監督式分群中，由於沒有真實標籤 \(y\)，無法計算準確率。考題與實務中評估分群品質的兩大黃金準則：

① 輪廓係數 (Silhouette Coefficient)： 範圍在 \([-1, 1]\)。 \[s(i) = rac{b(i) - a(i)}{\max(a(i), b(i))}\] 其中 \(a(i)\) 為同群樣本平均距離（凝聚度），\(b(i)\) 為最近異群樣本平均距離（分離度）。越接近 \(+1\) 代表群內凝聚且群間分離越完美；接近 0 代表邊界重疊；負值代表分錯群。
② 肘部法則 (Elbow Method)： 針對 KMeans 計算不同 \(K\) 值的群內平方和誤差 (Inertia / WCSS)。當 \(K\) 增加時誤差下降，曲線由陡峭急遽變為平緩的拐點（Elbow 肘部）即為最佳推薦群數。

總訓練次數 = 參數候選組合總數 × \(cv\) 折數 （若 refit=True 則在全集上額外 + 1 次）

例：{'n_estimators': [50, 100], 'max_depth': [3, 5, 10]}。共有 \(2 imes 3 = 6\) 組參數組合；若設定 \(cv=5\)，則在折疊交叉驗證中共訓練 \(6 imes 5 = 30\) 次。因為 refit=True，最終以最優參數在完整全量數據集上額外訓練 1 次，總共訓練 31 次！

黃金實踐程式碼：GridSearchCV 網格調參範本

}

    estimator=RandomForestClassifier(random_state=42),
    param_grid=param_grid,
    cv=5,
    scoring='roc_auc',
    refit=True

MLP(nn.Module) / PyTorch 訓練迴圈 —— 信號管線與連鎖求導

torch.nn & torch.optim
真題對位：L23203 / 官方真題 Q44 (訓練代碼除錯)
費曼白話直覺：「信號放大管線與壓力波倒震」

神經網路是一條由「可調旋鈕 \(W\)」與「非線性閘門（激活函數）」串聯的管線。前向推論是信號從左流向右邊出口；計算損失是用尺量出出口與標準答案的距離標量；反向傳播（loss.backward）是一道壓力波從出口往入口倒著震回去（微積分鏈式法則連鎖律），各旋鈕記錄震動敏感度（梯度 .grad）；梯度下降（optimizer.step）就是所有旋鈕照著記錄的角度同時微調一步！

① zero_grad()
清空上一輪累加梯度
② model(X)
前向傳播建構 DAG
③ criterion()
計算損失純量偏差
④ backward()
連鎖求導計算梯度
⑤ step()
同步微調更新權重
黃金實踐程式碼：PyTorch XOR 求解標準訓練迴圈 
import torch
import torch.nn as nn
import torch.optim as optim

# 1. 定義管線
model = nn.Sequential(
    nn.Linear(2, 4),   # W1 升維投影
    nn.ReLU(),         # 非線性二極體閘門，折彎特徵空間切分 XOR
    nn.Linear(4, 1),   # W2 降維輸出
    nn.Sigmoid()       # 壓縮至 [0, 1] 機率
)

criterion = nn.BCELoss()  # 損失標尺：僅測量偏差，絕不自動計算梯度！
optimizer = optim.SGD(model.parameters(), lr=0.1)

# 2. 訓練四部曲
for epoch in range(1000):
    optimizer.zero_grad()          # ① 歸零歷史梯度
    y_pred = model(X)              # ② 前向傳播
    loss = criterion(y_pred, y)    # ③ 計算純量損失
    loss.backward()                # ④ 鏈式求導更新各層 .grad
    optimizer.step()               # ⑤ 沿著負梯度更新權重 W
順序顛倒與漏寫之三大反事實災難
  • 災難 1（漏寫 optimizer.zero_grad）： PyTorch 預設梯度會持續累加（+=）。如果不清空，梯度隨輪次暴增數千倍，引發梯度爆炸（Gradient Explosion），權重數值溢出為 NaN！
  • 災難 2（漏寫 loss.backward）： 網路中所有權重的 .grad 均為 None 或 0，後面的 optimizer.step() 更新幅度為 0，模型權重完全凍結，永遠無法學習！
  • 災難 3（把 zero_grad 放在 backward 後面但在 step 前面）： 剛算好的梯度在更新前一瞬間被直接抹除歸零，導致權重同樣完全無法更新！

import torch
import torch.nn as nn
import torch.optim as optim

def test_mlp_xor_backprop_contract() -> None:
    torch.manual_seed(42)
    X = torch.tensor([[0., 0.], [0., 1.], [1., 0.], [1., 1.]], dtype=torch.float32)
    y = torch.tensor([[0.], [1.], [1.], [0.]], dtype=torch.float32)
    
    model = nn.Sequential(nn.Linear(2, 4), nn.ReLU(), nn.Linear(4, 1), nn.Sigmoid())
    criterion = nn.BCELoss()
    optimizer = optim.SGD(model.parameters(), lr=0.1)
    
    optimizer.zero_grad()
    y_pred = model(X)
    loss = criterion(y_pred, y)
    loss.backward()
    
    # 斷言：各層參數之 .grad 必須存在且不為 None
    for param in model.parameters():
        assert param.grad is not None, "反向傳播未穿透所有隱藏層"
        assert not torch.isnan(param.grad).any(), "梯度溢出為 NaN"
    
    optimizer.step()
【知識補充專題 6 & 7】分類評估指標雷達 (ROC vs PR) & PyTorch 動態計算圖與 Autograd 機制

1. 分類指標矩陣與極度不平衡評估陷阱

指標名稱 計算公式 業務直覺與代表情境 iPAS 題眼避坑關鍵
Accuracy 準確率 \(\frac{TP + TN}{TP + TN + FP + FN}\) 全集整體預測正確比率 樣本極端失衡時完全失真，嚴禁作為唯一指標！
Precision 查準率 \(\frac{TP}{TP + FP}\) 寧缺毋濫：預測為陽性中真實陽性比率（垃圾郵件、投資薦股） 代價在於誤報 (FP) 成本極高時優先提升 Precision
Recall 召回率 \(\frac{TP}{TP + FN}\) 寧可錯抓不可漏放：真實陽性中被成功抓出比率（癌症篩檢、地震預警） 漏網之魚 (FN) 會出人命時，Recall 必須優先極大化！
F1-Score \(2 \cdot \frac{P \cdot R}{P + R}\) Precision 與 Recall 的調和平均數 (Harmonic Mean) 調和平均對極端偏小的值懲罰嚴厲，杜絕偏科模型

ROC-AUC vs. PR-AUC： ROC 曲線橫軸為 FPR (\(FP / N\))，當負樣本母體極巨大時，FPR 分母被稀釋，ROC 曲線容易給出過於樂觀的虛高分數； 在信用卡盜刷或罕見疾病等極度失衡任務中，官方考綱推薦採用 PR-AUC (Precision-Recall AUC) 作為更可信的評估準則！

2. PyTorch 動態計算圖 (DAG) 與 Autograd 機制剖析

動態構圖 (Define-by-Run)： 每次前向傳播 \(y = \text{model}(X)\) 執行時，PyTorch 即時在記憶體中建立有向無環圖 (DAG)。葉節點 (Leaf Tensors) 是模型權重 \(W, b\)，非葉節點儲存前向計算值與對應的求導梯度函數 (如 grad_fn=<ReluBackward0>)。
推論記憶體優化： 在驗證與測試集推論時，必須使用 with torch.no_grad(): 上下文管理器，強制關閉計算圖建構與梯度歷程追蹤，可節省超過 50% 的顯存並提升 2~3 倍推論速度！
