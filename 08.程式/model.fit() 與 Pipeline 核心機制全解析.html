核心觀念破題

在機器學習中，Model Fit（模型訓練 / 擬合）與 Pipeline（資料管線）是完全不同層次的概念。簡單來說：Model Fit 是「動作/方法」（讓模型去學習資料），而 Pipeline 是「容器/架構」（把多個步驟與模型串接成一條龍的工具）。

概念解析 01

什麼是 Model Fit？（學什麼、做什麼）

● 定義： fit() 是機器學習演算法（如邏輯斯迴歸、隨機森林、SVC 等）或前處理工具（如 StandardScaler）的「訓練 / 學習」方法。
● 核心功能： 讓物件從輸入的資料（\(X, y\)）中計算並記憶參數。
  • 讓 StandardScaler.fit(X) 算出整筆資料的「平均值」與「標準差」。
  • 讓 LinearRegression.fit(X, y) 算出迴歸線的「權重（weights）與截距（intercept）」。
● 實質特點： 「Fit 就是學」—— 每一站把學到的參數存進自己的口袋。單獨對單一模型執行 model.fit(X, y)，只會訓練該模型本身，無法自動協調前面的資料轉換步驟。
角色定位：動詞 (Verb) / 參數計算與儲存
概念解析 02

什麼是 Pipeline？（結構、功能）

● 定義： Pipeline（管道 / 流水線）是一個將「資料前處理步驟」與「最終機器學習模型」依序打包在一起的容器物件。
● 核心功能： 把一連串動作串成一條生產線（例如：資料輸入 ➔ 標準化 (Scaler) ➔ 降維 (PCA) ➔ 分類模型 (Classifier)），統一管理整個流程的執行順序。
● 最大優點（防 Data Leakage 資料洩漏）：
  • 當呼叫 pipeline.fit(X_train, y_train) 時，它會自動依序對每一站呼叫 fit，在交叉驗證中嚴格確保前處理只用訓練集算統計量，避免偷看未來資訊。
  • 呼叫 pipeline.predict(X_test) 時，資料會自動流過前面所有設定好的 transform，最後才交由模型預測。
角色定位：名詞 (Noun) / 多階段串接容器
Model Fit vs Pipeline 核心差別快速對照表 Scikit-Learn 架構基礎
比較維度 Model Fit (model.fit) Pipeline (Pipeline)
本質 是一個方法（Method / Function） 是一個物件 / 架構（Object / Wrapper）
主要角色 負責讓單一元件「從資料中學習參數」 負責把「多個前處理步驟與模型」串接成一條龍
操作對象 單一 Estimator 或 Transformer 一組按順序排列的 (name, transformer/estimator) 列表
與 Fit 的關係 fit() 是動詞，用來執行學習動作 你可以對整條 Pipeline 執行 pipeline.fit()，它會連動去幫裡面每一站執行 fit

fit() 與 transform() 數學本質剖析

以特徵標準化 (Z-Score) 為例
1. fit(X) 的本質 統計量參數估計 (Learn Parameters)

只計算並儲存數據分佈特徵

執行 fit() 時，並不會改變原始資料數值。估計器只遍歷輸入的特徵維度，計算樣本平均數 μ 與標準差 σ 並保存在內部狀態中（如 scaler.mean_ 與 scaler.scale_）。

數學公式：
$$\mu = \frac{1}{N}\sum_{i=1}^{N} x_i, \quad \sigma = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_i - \mu)^2}$$
⚠️ 關鍵規則： 嚴格只能在 訓練集 (Train Set) 上呼叫 fit()！
2. transform(X) 的本質 數值位移與縮放 (Apply Transform)

套用已學會的統計量進行轉換

執行 transform() 時，不再重新計算均值與標準差，而是直接調用先前 fit() 留下的 μtrain 和 σtrain，將給定數據投影到標準常態分佈空間中。

轉換計算：
$$z_{\text{any}} = \frac{x_{\text{any}} - \mu_{\text{train}}}{\sigma_{\text{train}}}$$
✅ Pipeline 的好處： 測試集送進去時，Pipeline 自動使用訓練集學到的 μtrain 進行轉換，絕不重新計算測試集本身的均值。

Scikit-Learn 最佳實踐
錯誤做法：在分割前進行全局 fit_transform Data Leakage! 
# ❌ 典型錯誤範例：全域前處理導致洩漏
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

# 致命錯誤：對所有資料 (包含即將被切出去的測試集) 一起計算 mu 和 sigma！
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)  # ❌ 測試集統計量被吸收了

# 分割資料
X_train, X_test, y_train, y_test = train_test_split(
    X_scaled, y, test_size=0.2
)

model = LogisticRegression()
model.fit(X_train, y_train)
score = model.score(X_test, y_test)  # 虛高的指標，上線即劣化
盲點： 在交叉驗證 cross_val_score 前若先跑了全局特徵選擇或標準化，每一折驗證集都已知曉全域分佈。
規範做法：使用 Pipeline 封裝完整流程 Production Ready 
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, train_test_split

# 1. 建立管線：定義步驟 (轉換器 + 最終評估器)
pipe = Pipeline([
    ('scaler', StandardScaler()),       # 必須實作 fit & transform
    ('classifier', LogisticRegression()) # 必須實作 fit
])

# 2. 正確交叉驗證：每一折內部自動獨立 fit_transform
scores = cross_val_score(pipe, X, y, cv=5)

# 3. 實務訓練與部署
pipe.fit(X_train, y_train)
# 推論時自動套用訓練集之 mu/sigma 進行 transform，再 predict：
preds = pipe.predict(X_test)
優勢： 程式碼緊湊、超參數可用 GridSearchCV(pipe, param_grid={...}) 聯合搜尋，且徹底杜絕洩漏。

歷屆考點 01 機器學習模型評估與特徵工程規範

【單選題】在機器學習建模流程中，若在進行 K-Fold 交叉驗證之前，就對「全體資料集」執行缺失值中位數填補與特徵正規化，會造成下列何種最直接的後果？

IPAS 官方解析重點： 在切分資料前對全體數據進行填補或正規化，驗證集（Validation Fold）的資訊（如中位數、平均值）已經混入了預處理參數中。這稱作資料外洩（Data Leakage）。正確做法是使用 Pipeline，讓交叉驗證的每一折都在各自的訓練折上計算統計量，再套用至驗證折。

IPAS 官方解析重點： 選項 C 錯誤。在推論階段呼叫 predict(X_test) 時，Pipeline 的中間 Transformer 只會呼叫 transform()，直接使用先前訓練時學到的統計量進行轉換，絕對不能再次呼叫 fit 或 fit_transform。
